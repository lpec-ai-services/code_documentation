# The `VTKExport` post-processing

The `VTKExport` post-processing exports a set of fields to a VTK
file readable in `paraview`.

The `VTKExport` post-processing was developped before the
introduction of the `manta` layer and suffers from various
shortcomings. In particular, the `VTKExport` post-processing can
only export fields registred in an internal database.

The `manta` layer automatically registers many fields in this
database, for instance unknowns calculated by models or, gradients,
thermodynamics forces and internal state variables defined by
behaviors. However, it only covers a limited subset of quantities of
interest for post-processing.

In particular, only *true* fields (see Section [User guide for Fields](../../manta_components_user_guide/main_user_concepts/user_guide_objects/user_fields.md#user-fields)) can be
registred in this database, as opposed to the concept of evaluators used
by the `manta` layer to generalise the notion of field (see
Section [The evaluators](../../developer_guide/services/evaluators.md#evaluators)).

Moreover, this database exposes details that are normally hidden by the
`manta` layer. For instance, state variables are all grouped in a
single field, but the `manta` layer exposes each individual state
variable as a view to this single field (using dedicated evaluators).
Post-formulations objects does not support such views.

## Limitations

The `VTKExport` post-processing strives to hide those shortcomings
as much as possible but some consequences of this design are
unavoidable:

- The initialization of the `VTKExport` post-processing may fail if
  the user request a quantity which is not defined by a *true* field.
  For example, a property computing the Young's modulus can't be
  exported by the `VTKExport` post-processing.
- When requesting a state variable, the field containing all the
  internal state variables is exported. The name of this field is
  generally cryptic: a typical example is *internal state variable of
  behavior 'Plasticity' at the end of the time step*. The name of the
  requested state variable is not present in the file generated by the
  post-processing and the user must find a way to extract the relevant
  information.
- All fields registred in the internal database with the same name
  are exported together. Hence, even if the temperature is requested on
  a single material, the resulting file will contain the temperature on
  all materials described by the heat transfer model.

## Parameters

- `outputFileBaseName`: base name of the output file name. For
  example, if this parameter is set to `EquivalentPlasticStrain`,
  `VTKExport` post-processing generates a file named
  `EquivalentPlasticStrain.pvd` and a directory named
  `EquivalentPlasticStrain_vtk`.
- `outputFormat`: output format. Valid values are `binary`
  and `ascii`.
- `exportFieldsAtIntegrationPoints`: boolean stating how fields
  at integration points are treated. If true, value at all integration
  points are exported. If false (which is the default), fields at
  integration points are averaged on each element.
- `fieldsNamesAsDeclaredInPostFormulations`: list of field names
  registred in the internal database. This parameter must be used with care
  as it exposes the internals on how the Manta' VTK writer works. Use this
  parameter at your own risks.
- `allTimeSteps`: boolean stating if the fields must be written
  at each time step or at the end of each temporal sequence (default
  option).
- `fields`: list of fields to be
  processed. Each entry must be a dictionary
  containing three entries `field`, `fieldType` and a third entry
  giving the location of the field to be processed:

  - The `field` entry gives the name of the field.
  - The `fieldType` must be either `nodeField` or `ipField`.
  - The third parameter can be any of `domain`,
    `material`, `domains` or `materials`.

## Example of usage

PYTHON

```python
ps.addPostProcessing('VTKExport',
                     outputFileBaseName = 'EquivalentPlasticStrain',
                     fields = [{'field': 'EquivalentPlasticStrain',
                                'fieldType': 'ipField',
                                'material': 'cube'}])
```

C++

```c++
ps->addPostProcessing(ctx, "VTKExport",
                      Parameters{
                          {"outputFileBaseName", "EquivalentPlasticStrain"},
                          {"fields", Vector<Parameters>{Parameter{
                                         {"field", "EquivalentPlasticStrain"},
                                         {"fieldType", "ipField"},
                                         {"material", "cube"}}}}});
```
