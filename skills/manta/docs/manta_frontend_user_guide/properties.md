# Properties

Model bricks are generally expressed in a generic manner and delegates
the knowledge about materials or structures to behaviors and/or
properties. Likewise, some behaviours may require some properties. For
examples:

1. A brick describing the evolution of the specific enthalpy may require
   a property giving the mass density and the specific heat capacity.
2. An isotropic elastic material under the infinitesimal perturbation
   hypothesis is described by Hooke's law. A generic implementation of
   this law may require the Young's modulus and Poisson's ratio as
   properties. Another implementation may use Lamé's coefficients.
3. A brick computing the inner forces an isotropic elastic beam may
   require the moment of inertia.

A property is associated to a material, a structure using the
`addProperty` method of a `PhysicalSystem`.

PYTHON

```python
ps.addProperty('Constant',
               name = 'YoungModulus',
               material = 'FuelPellet',
               value = 150e9)
```

C++

```c++
const auto r = ps.addProperty(ctx, "Constant",
                              Parameters{{"name", "YoungModulus},
                                         {"material", "FuelPellet"},
                                         {"value", 150e9}}));
```

Note

It is important to notice that the property is not attached
directly to a brick for at least three reasons:

1. The brick may rely on a behaviour and may not know which
   properties are required by the brick.
2. Several bricks or behaviors may use the same property.
3. It may be convenient to declare properties that will not be used
   during the simulation for reasons explained in Section
   [External material databases](#external-material-databases).

There are several implementations of material properties described in
Section [Available properties implementations](#available-properties-implementations).

See also

Further help about available properties can be found in the
`Properties` section of the online help which is accessible in
`python` through the `manta.info` function or through the
`manta-info` utility (see Section [The manta-info utility](miscellaneous/tools.md#manta-info-utility)).

PYTHON

```python
manta.info('Properties')
```

SH

```sh
manta-info Properties
```

## External material databases

A property participates to the resolutions of the dependencies. If a
property does not resolve any dependency, it will not be evaluated
during the simulation. Declaring unused properties is thus mostly free.

This can be very useful in pratice as the user may import all the known
properties of a material from a material database.

For example, a team or a project may maintain a material database for
the *316LN* stainless steel an provides an extension to Manta
providing a defineProperties function that could be used as follows:

```python
defineProperties(ps, domain = "ReactorVessel", material = "316LN")
```

## Available properties implementations

### The `Constant` property

The `Constant` property defines a constant scalar property.

#### Parameters

The following parameters are allowed:

- `name`: the name of the property
- `value`: the value of the property
- `domain`: domain (regular expression) on which the property is defined (equivalent to `material`).
- `material`: material (regular expression) on which the property is defined (equivalent to `domain`).
- `domains`: domains (regular expressions) on which the property is defined (equivalent to `materials`).
- `materials`: materials (regular expressions) on which the property is defined (equivalent to `domains`).

#### Example

PYTHON

```python
ps.addProperty('Constant',
               name = 'YoungModulus'
               material = 'FuelPellet'
               value = 150e9)
```

C++

```c++
const auto r = ps.addProperty(ctx, "Constant",
                              Parameters{{"name", "YoungModulus"},
                                         {"material", "FuelPellet"},
                                         {"value", 150e9}}));
```

### The MFront property

The `MFront` property calls a property generated using MFront.
Currently, only properties generated with the Cast3M interface are
supported.

Warning

Using MFront properties is convenient. However, in engineering studies,
the properties used must be covered by a rigourous Verification and Validation proces.
See Section [Advices on the management of MFront material knowledge](miscellaneous/mfront_material_knowledge_management.md#mfront-material-knowledge-management) for details.

#### Parameters

The following parameters are allowed:

- `name`: the name of the property.
- `library`: path to the MFront library (string).
- `property`: name of the function generated by MFront implementing the property (string).
- `domain`: domain (regular expression) on which the property is defined (equivalent to `material`).
- `material`: material (regular expression) on which the property is defined (equivalent to `domain`).
- `domains`: domains (regular expressions) on which the property is defined (equivalent to `materials`).
- `materials`: materials (regular expressions) on which the property is defined (equivalent to `domains`).

#### Example

PYTHON

```python
ps.addProperty('MFront',
               name = 'YoungModulus',
               material = 'ReactorVessel',
               library = 'libSS316LNMaterialProperties.so',
               function = 'SS316LN_YoungModulus_RCCMR2014')
```

C++

```c++
const auto r = ps.addProperty(ctx, "MFront",
                              {{"name", "YoungModulus"},
                               {"material", "ReactorVessel"},
                               {"library", "libSS316LNMaterialProperties.so"},
                               {"function", "SS316LN_YoungModulus_RCCMR2014"}})
```

## Defining properties using user defined functions

User-defined functions depending on one or two variables may be directly
used as properties using the addProperty method. The last argument(s)
must be the name of the variable(s) used to evaluate the user-defined
function.

Warning

Using user-defined function may seem pratical at first sight but may cause serious issues regarding Verification
and Validation processes. For example, those user-defined functions can be duplicated in each new study by
copy/pasting lines of codes.
Their usage is thus discouraged in engineering studies in favor of building
rigorous material databases. See Section [Advices on the management of MFront material knowledge](miscellaneous/mfront_material_knowledge_management.md#mfront-material-knowledge-management).

### Example

PYTHON

```python
ps.addProperty('YoungModulus', 'Cladding',
               lambda T: 127.8e9 * (1- 7.825e-5 * (T - 293.15)),
               'Temperature')
```

C++

```c++
const auto r = ps.addProperty(ctx, "YoungModulus", "Cladding",
                              [](const Real T) { return 127.8e9 * (1- 7.825e-5 * (T - 293.15));},
                              "Temperature")
```

## Defining constant spatially variable properties

In Python, the `addConstantSpatiallyVariableProperty` allows to define
a constant (in time) property by a function of the coordinates.

### Example

The following code defines the property `testProperty` on the
material `cube` using the function \(f(x, y) = x + 2y\) in
\(2D\):

PYTHON

```python
def f(x, y):
 return x + 2 * y

ps.addConstantSpatiallyVariableProperty(f, name = 'testProperty',
                                        material = 'cube')
```

### Parameters

The following parameters are allowed:

- `name`: name of the loading.
- `domain`: domain name (regular expression) (equivalent to material).
- `domains`: domains names (regular expressions) (equivalent to
  materials).
- `material`: material name (regular expression) (equivalent to
  domain).
- `materials`: materials names (regular expressions) (equivalent
  to domains).
