Chapter 40
DEPLETION CALCULATION
Depletion calculations allow computing kef fective, burnup, isotopic inventories and derived physical quantities
(such as mass or activity) after irradiation and/or decay period. This is done by solving the Boltzmann / Bateman
coupled system of equations. Bateman’s equations are solved by the MENDEL [48] depletion solver,
and the neutron flux is estimated by regular Monte Carlo simulation. In Monte Carlo burnup calculations,
statistical uncertainties propagation has to be taken into account, which is achieved by running independent
simulations. The procedure for managing independent simulations is automatized via a dedicated launcher
(see section 40.2) and distinct post-processing tools (see section 40.5).

## 40.1 DEPLETION CALCULATION INPUT FILE

An input deck for a depletion calculation is structured as follows :
• a TRIPOLI-4 static input file with some modifications explained below
• an input file containing the COMPOSITION block to specify the initial compositions
• an input file containing the GRID_LIST block
• an input file to specify the irradiation history

pointing to specific files :

Where:
• PWPG: Renormalization to the power expressed in W/gheavy_nuclides. Only depleted compositions may
be selected for the calculation of the power and the initial mass of heavy nuclides. By default, without
specification, the normalization is performed over all depleted compositions.
• POWER: Renormalization to the power (in W). The power is computed as the sum of the power of the
selected depleted compositions. By default, without specification, the normalization is performed over
the sum of all depleted compositions powers.
• FLUX: Renormalization to the flux intensity specified by fluxintensity. This flux corresponds to the
total flux cumulated over the selected compositions or volumes (but not limited to depletion regions)
integrated in both energy and space. By default, without specification, the normalization is performed
over the whole geometry. The GLOBAL_SCORES keyword has to be added in the SIMULATION block.
• FIXED_SOURCE: No renormalization is performed, the flux level is defined via the norm specified in the
SOURCE block.

compositions on which the normalization is performed using the keyword LIST. The selected volumes (or
compositions) must have compositions that belong to the depleted composition list when using the keywords
PWPG and POWER. If no selection of volumes or compositions is provided by the user, the normalization is
performed over all depleted compositions for the PWPG and POWER normalization methods, and the whole
geometry for the FLUX method. Below is an example of a normalization using the power over three volumes.

The POINTWISE_REACTION_RATES command is used to specify the nuclides for which all the reaction rates
are directly calculated by TRIPOLI-4. The reaction rates of the other nuclides are computed from multigroup
cross-sections (GENDF, Groupwise Evaluated Nuclear Data File) and the multi-group flux (defined
on the same energy grid). This introduces an approximation but reduces sensibly the computation time. It is
recommended to compute at least U238 reaction rates directly by TRIPOLI-4. This choice of nuclides applies
to all the depleted compositions. The POINTWISE_REACTION_RATES command is optional; by default, all
the reaction rates (defined in the depletion chain) are directly calculated by TRIPOLI-4. The syntax is
as follows:
POINTWISE_REACTION_RATES
*
ALL
*
LIST n NUC1 ... NUCn
*
FILE nuclide_list_file
Where:
• ALL : All the reaction rates are calculated by TRIPOLI-4. Thus, the number of responses will be typically
high (∼thousands). The use of this option will typically sensibly increase the duration of the neutron
transport simulation.
• LIST : For the n nuclides specified in this list, reaction rates are calculated by TRIPOLI-4. LIST 0
allows reconstructing all the reaction rates from the multi-group flux and GENDF cross-sections.
• FILE : If the nuclide list is too long, it is possible to write it in the file nuclide_list_file. No command
should be specified in it.

The ISOTOPIC_FILTERS command is optional. It allows defining filters on nuclides to be taken into account
during the transport calculation. These filters are applied at each time step, on each depleted composition. It
allows saving calculation time. Three kinds of filter are available:
• MIN_CONC: A filter on the minimal concentration required for a nuclide to be taken into account during
the transport step. This filter is actually applied by default with a value of 10−20 atoms per 10−24cm3.
This keyword can be used to modify the default threshold value.
• ABSORPTION_RATIO: A nuclide is taken into account in the transport calculation if the ratio of its
macroscopic disappearance rate over the one of the composition is larger than the threshold set by the
user.
• FISSION_RATIO: Same behaviour as the previous filter, but applied to macroscopic fission.
The syntax is as follows:

<!-- page 453 -->
ISOTOPIC_FILTERS n
MIN_CONC conc
ABSORPTION_RATIO abs_ratio
FISSION_RATIO fiss_ratio
Where :
• n: number of isotopic filters
• MIN_CONC : Allows redefining the threshold value of the minimal concentration filter. This threshold
will be set to conc.
• ABSORPTION_RATIO : Allows setting the threshold value of the ratio to abs_ratio.
• FISSION_RATIO : Allows setting the threshold value of the ratio to fiss_ratio.
Minimal concentration filter is applied first. The remaining isotopes are selected for the transport step if they
satisfy at least one of the two filters (ABSORPTION or FISSION).
The volume of each depleted composition is mandatory since reaction rates or flux estimated by TRIPOLI-4
are integrated over the volume, while the MENDEL depletion solver needs volumic reaction rates. The volumes
can be automatically computed by TRIPOLI-4 either for a native or a ROOT geometry (CALCULATION
block has to be used without the SET keyword, see Chapter 19 for more details). The geometrical frame
must include all the depletion regions. The automatic calculation of the volumes can lead to large computation
time. Consequently, it is recommended to provide the volumes (in cm3) for all depleted compositions
whenever possible. This can be done by the optional command VOLUMES.

### 40.1.3 INITIAL COMPOSITIONS FILE

This file contains the COMPOSITION block in which all the initial compositions of the system (depletion
regions or not) are specified. It follows the syntax described in Chapter 10 except that depleted compositions
can only be defined with the POINT_WISE keyword (in 1024 atoms per cm3) or with the DENSITY keyword
(density in g·cm−3 and the mass fraction of each isotope).
At initialization step, depleted compositions described with the DENSITY keyword (if any) are converted to
atoms per cm3 (POINT_WISE keyword). This file is stored in the result directory (resultdirectoryname/compos
.jdd). It will be updated at each depletion step.

## 40.2 LAUNCHING INDEPENDENT SIMULATIONS

In Monte Carlo burnup calculations, statistical uncertainties propagation has to be taken into account, which
is achieved by running independent simulations. The procedure for managing independent simulations is
automatized via a dedicated launcher that allows launching them in parallel.
A depletion calculation input deck must be modified as follows :
1. a resultdirectoryname must be specified with the RESULT_DIRECTORY command in the RESULTS block
2. no random seed must be set in the SIMULATION block
Independent simulations launchers named “launch_jobT4_IndepSimu_<arch>.sh" can be found in the
“launcher" directory of the TRIPOLI-4 distribution. “arch" depends on the hardware architecture used.
The following architectures are available: workstations, slurm for clusters using SLURM or gridengine for
clusters using SGE.

<!-- page 457 -->
The use is :
launch_jobT4_IndepSimu_workstations.sh <machines-file> <nbsimu> <startrank>
-d <inputfile> [-s <format>] [-c <pathfile>] [-l <language>] [other T4 options...] ...
launch_jobT4_IndepSimu_slurm.sh <nbproc> <nbsimu> <startrank> <time>
-d <inputfile> [-s <format>] [-c <pathfile>] [-l <language>] [other T4 options...] ...
where, concerning the first group of options :
• machines-file (workstations case) (mandatory) is the name of a file containing as many network hostname
as the number of independent simulations the launcher will then have the possibility to launch
• nbproc (cluster case) (mandatory) is the number of processors the launcher will ask
• nbsimu (mandatory) is the number of independent simulations (nbsimu <= nbproc)
• startrank (mandatory) is the rank of the first independent simulation to launch (useful if the desired
nbsimu is greater than the number of processors available at a time)
• time (mandatory) (cluster) is the total duration of the job on a cluster
and concerning the second group of options :
• -d <inputfile> (mandatory) is the input deck with the modifications mentioned above
• -s <format> (optional) is the format for the cross-sections. Default is NJOY.
• -c <pathfile> (optional) is the file containing the access paths for the nuclear data required by the code.
Default file is the one configured with the distribution.
• -l <language> is used to indicate the language used when entering the keywords. The default value is
“old".
• see chapter 1 for other options
First, a pretreatment step creates as many input decks and result directories as the number of independent
simulations. Such a created input deck is characterized by its own random seed and by its own resultdirectoryname
. Created input decks and result directories are identified with their simulation rank.
Then, independent simulations are launched in parallel. The results can be post-processed using tools described
in section 40.5.

## 40.3 RESTART CALCULATION

It is possible to restart a calculation from an arbitrary depletion step. This is one of the reasons why compos
.jdd and compos_mendel.jdd files are saved at each depletion step. The procedure to restart from the Nth
depletion step is the following:
1. it is recommended to save the output directory

<!-- page 458 -->
2. in the output directory, replace the file compos.jdd by the file compos_N.jdd
3. in the output directory, replace the file compos_mendel.jdd by the file compos_mendel_N.jdd
4. use the script Restart.py to remove results corresponding to depletion steps higher than N in the ROOT
output file and to produce the restart_info file.
5. replace the current ROOT output file and the restart_info files by the new restart_info and ROOT output
file produced by the script Restart.py.
6. Launch the simulation
If the simulation stopped accidentally (simulation time exceeds the time requested to the cluster scheduler, ...),
in most cases, it is possible to restart the calculation just by launching again the calculation. The simulation
should restart from the current depletion step. The only exception concerns the calculations that have not
stopped during the transport calculation (most of the time is spent in this step). It is recommended to restart
from the previous step by resorting to the procedure detailed above.

## 40.4 USING THE SOURCE FROM THE PREVIOUS DEPLETION STEP

Since version 8.1, it is possible to store source particles in an ASCII or binary file and use these particles as a
discrete source for another calculation. This functionality can be adopted to use the source of the last batch of
the previous depletion step as a source for the current depletion step. The process has to be initialized by an
extra calculation to produce the file for the first depletion step using the keyword STORE_SOURCES_IN_FILE
in the SIMULATION block. Then, it is just necessary to have STORE_SOURCES_IN_FILE command in the
SIMULATION block and also a source using this file. The source file is automatically updated at each time step.

## 40.5 RESULTS AND POST-PROCESSING

All the results of a depletion calculation are stored in an output directory whose name is specified by the
RESULT_DIRECTORY keyword.

### 40.5.1 CONTENT OF THE OUTPUT DIRECTORY

The output directory of a depletion calculation is composed of the following files:
• the ROOT output file aggregating all the simulation results (see 40.5.2)
• the file compos_mendel.jdd containing the COMPOSITION block of the last depletion step. This file is
updated at each depletion step.
• the files compos_mendel_i.out (where i is depletion step index) are copies of the file compos_mendel.jdd
made at each depletion step.

<!-- page 459 -->
• the file compos.jdd containing the COMPOSITION block of the last depletion step. This file is updated at
each depletion step. It contains only nuclides that have not been removed from the transport calculation
(see ISOTOPIC_FILTERS command).
• the files compos_i.out (where i is depletion step index) are copies of the file compos.jdd. This allows
easily performing a static calculation at a specific time step.
• the files reponses.jdd and scores.jdd respectively contain the RESPONSES and SCORE blocks. They are
automatically built from the depletion chain, the list of depleted compositions and the reaction rates
calculation options.
• the output of the transport calculation (t4output file). By default, only the last depletion step file is
preserved. This file can be saved at each depletion step by resorting to the SAVE_T4LISTING keyword.

### 40.5.2 CONTENT OF THE ROOT OUTPUT FILE

At each depletion step, results are stored in two ROOT tree structures (TTree class): a tree called evoltree
containing all the depletion results and a tree called evolflux containing the multi-group flux of each depleted
composition (if the option WRITE_FLUX is enabled).
The evoltree tree is composed of branches, each attached to a physical quantity:
• step_num: the depletion step index
• burnup: the mean burnup of the system in MWd·t−1
HN
• cumulirradtime: the cumulative irradiation time in s
• irradtime: the duration of the next depletion step in s
• kcoll: ke f f (collision estimator)
• ktrack: ke f f (track length estimator)
• kstep: ke f f (generation estimator)
• beff_prompt: βef f computed by the "prompt" method, in 105 pcm
• beff_nauchi: βef f computed by the "Nauchi" method, in 105 pcm
• total_powereffect: the power cumulated on all the depletion regions expressed in W
• renormfact: the factor by which the reaction rates and fluxes are multiplied to obtain the normalization
specified with the RENORMALIZATION command.
• compo_name: the name of the current depletion region
• compo_vol: the volume in cm3 of the current depletion region
• local_burnup: the burnup of the current depletion region in MWd/tHN

<!-- page 460 -->
• therm_flux: the flux in the current depletion region in the first energy group of DEC_2G in neutrons ·
cm−2 ·s−1
• fast_flux: the flux in the current depletion region in the second energy group of DEC_2G in neutrons ·
cm−2 ·s−1
• powereffect: the power in the current depletion region in W
• isotope_name: the current nuclide name
• A: the mass number of the current nuclide
• punctual (pointwise in activation calculations; see Chapter 41): specifies whether the reaction rates of
the current nuclide are computed directly by TRIPOLI-4 (1) or if they are computed from the multigroup
flux and the GENDF cross-sections
• transport: specifies whether the current nuclide has been taken into account in the transport calculation
(1)
• isotope_conc: concentration of the current nuclide in atoms per 10−24cm−3
• mass: mass of the current nuclide in g
• activity: activity of the current nuclide in Bq per cm3
• reaction_name: the name of the current reaction
• reactionrateg1: microscopic and volumic reaction rate of the current reaction. Fast energy group if the
current reaction is fission, energy integrated for all other reactions.
• reactionrateg2: microscopic and volumic reaction rate of the current reaction. Thermal energy group if
the current reaction is fission, zero for all other reactions.
If the WRITE_FLUX keyword is specified in the DEPLETION block, the evolflux tree containing the flux computed
on the DEC_FLUX_MULTIG energy grid for each depleted composition. It has the following structure:
• stem_num: the depletion step index
• renormfact: the factor by which the reaction rates and fluxes are multiplied to obtain the normalization
specified with the RENORMALIZATION command.
• compo_name: the current depleted composition name
• compo_vol: the volume in cm3 of the current depleted composition
• goup_id: index of the current energy group of the DEC_FLUX_MULTIG energy grid
• energy1: lower bound of the current group in eV
• energy2: upper bound of the current group in eV
• flux_val: flux value in the current group in neutrons·cm−2 ·s−1
Observe that this tree requires a large disk space for large systems. In these cases, it is recommended to set
WRITE_FLUX to 0.

### 40.5.3 POST-PROCESSING

The post-processing of a TTree structure is explained in great detail in the ROOT user’s guide. It allows easily
plotting physical quantities as a function of the time or burnup for one depletion calculation result, i.e. for
one independent simulation. However, it is difficult to post-process several independent simulations. To this
aim, post-processing tools, consisting mainly of two C++ classes, BurnupResults and MeanBurnupResults,
are available in TRIPOLI-4 and may be called either from a ROOT C++ script or a Python script.

#### 40.5.3.1 Post-processing a unique ROOT output file using BurnupResults class

Building a BurnupResults object requires only the path to the ROOT output file to be post-processed. Once
the object is built, the following methods allow obtaining the corresponding physical quantities at any
depletion step:
For global physical quantities:
• GetKcoll(int step)
• GetKtrack(int step)
• GetStep(int step)
• GetBeffPrompt(int step)
• GetBeffNauchi(int step)
• GetBurnup(int step)
• GetTime(int step)
• GetRenorm(int step)
• GetTotalPower(int step)
For the local physical quantities (i.e. for each depletion region):
• GetPower(int step, string componame)
• GetLocalBurnup(int step, string componame)
• GetFastFlux(int step, string componame)
• GetThermFlux(int step, string componame)
• GetMass(int step, string componame, string isotope_name)
• GetConcentration(int step, string componame, string isotope_name)
• GetActivity(int step, string componame, string isotope_name)
• GetReactionRate(int step, string componame, string isotope_name, string reaction_name)

#### 40.5.3.2 Post-processing several ROOT output files using the MeanBurnupResults class

At each independent simulation is associated to a ROOT output file. The MeanBurnupResults class allows
aggregating the results contained in each output file and computing means and their associated error bars on
all the previously listed physical quantities.
Building a MeanBurnupResults object does not require any information. To post-process a ROOT output file
it is just necessary to call the method AddSimulationAndProcess with the path to the ROOT output file. The
interface of the MeanBurnupResults class is the same as BurnupResults except for an additional parameter
(an integer) specifying the kind of value to be returned: the mean (0, default behavior), the standard deviation
of the mean (1) or the relative standard deviation in % (2).
The listings 40.3 and 40.4 are respectively C++ and Python examples of scripts resorting to the MeanBurnup
Results class to post-process 10 independent depletion calculations.

<!-- page 465 -->
#include "PREFIX/InitPostscripts.C"
void IndependentSimulationsAnalysis()
{
// Load postscripts classes
InitPostscripts();
const int nb_simus = 10;
// Create an object MeanBurnupResults
MeanBurnupResults m;
// Add ROOT output files to the MeanBurnupResults object
for (int i=0;i<nb_simus;i++) {
TString filename = "evolution_";
filename += (i+1);
filename += ".root";

}
// Print some mean values and their corresponding standard deviation at
// the last depletion step:
// M(U235) in depleted composition FUEL_R1,

cout << "(" << m.GetMass(last_step,"FUEL_R1","U235",1) << ")" << endl;

for (int i=0;i<6;i++) {
TString med("FUEL_R");
med += (i+1);

cout << "(" << m.GetLocalBurnup(last_step,med,1) << ")" << endl;

file << "\t" << m.GetKcoll(i+1,1) << endl;
}
file.close();
// Plot evolution of Kcoll vs. burnup
m.GetKcollGraph()->Draw("ale");

#### 40.5.3.3 Producing Tripoli-4 composition files from ROOT outputs

As of TRIPOLI-4 v12, the ROOT output file contains all the necessary information to reconstruct all the
TRIPOLI-4 compositions at any time step. The post-processing scripts in the postscripts directory make it
possible to produce text files containing a list of material compositions in the TRIPOLI-4 format (see Chapter
10). For a single simulation result, one can use the WriteT4CompositionFile() method of the BurnupResults
class:
import sys
sys.path.append("PREFIX")
# note: PREFIX must be replaced with the path to the ’postscripts’ folder
# containing the post-processing scripts
from InitPostscripts import InitPostscripts
InitPostscripts()
from ROOT import BurnupResults
# Create a BurnupResults object from the ’evolution.root’ output file
b = BurnupResults("evolution.root")
# Write a TRIPOLI-4 composition file called ’compos_1.t4’ containing the
# compositions after the first depletion step
b.WriteT4CompositionFile(’compos_1.t4’, 1)
# Same thing for the compositions after the fifth depletion step
b.WriteT4CompositionFile(’compos_5.t4’, 5)
