Chapter 19
THE WEIGHT WINDOWS VARIANCE
REDUCTION TECHNIQUE
The weight windows method is a variance reduction method, based on splitting and Russian roulette
operations, which can be used as an alternative to the standard variance reduction techniques of TRIPOLI-4®
presented in Chapter 17. This technique is commonly used by Monte Carlo transport codes, such as MCNP.
Notes:
• The implementation of the weight windows technique in TRIPOLI-4® allows for playing weight windows
games at several possible event types of particle trajectories, such as collision and surface crossing.
• Weight windows are available in TRIPOLI-4® only for spatial meshes superimposed on the geometry,
but are not available for volumes of the geometry.
• Weight windows games need the knowledge of so-called lower weight bounds (or lower bounds) data
which can be provided either by an importance map produced by the INIPOND module of TRIPOLI-4®
(see Chapter 17), or by adjoint fluxes values given on a spatial mesh and an energy grid (e.g. retrieved
from the output of a deterministic code), or by the output of version 3.0 of ADVANTG deterministic
code [90] (directly through a so-called wwinp file readable by version 5 of MCNP and also by TRIPOLI-
4® within the weight windows feature).
According to the common weight windows technique (see Reference [7]), each weight window is
defined by a lower weight bound Wl (threshold for the Russian roulette game, played for particles whose
statistical weight is below Wl), a survival weight Ws (outgoing weight of particles surviving the Russian
roulette game) and an upper weight Wu (threshold for splitting operations, played for particles whose
statistical weight is above Wu). No action is taken for particles within the window (statistical weights
between Wl and Wu). Only lower weight bounds data have to be given in each spatial cell and energy
group. Two constants, Cu and Cs (ratios also given as input data), allow to get Ws and Wu in all cells and
groups with the following relations:
Ws(P) = Cs Wl(P)

Wu(P) = Cu Wl(P)

Wl(P) =

(1+Cu) φ+(P)

where R is a total response renormalization factor and φ+(P) is the adjoint flux at P.
• When using weight windows, TRIPOLI-4® automatically applies importance values on the source (i.e.
source biasing), so as to simulate source particles with emission statistical weights already in agreement
with the weight windows data applying to the related source area. These importance values are retrieved
from the adjoint fluxes or derived from the lower bounds weight data, as given by the previous formula.

## 19.1 SYNTAX

As for the standard variance reduction technique of TRIPOLI-4® presented in Chapter 17, the syntax
for the weight windows technique is defined between the keywords VARIANCE_REDUCTION and
END_VARIANCE_REDUCTION with the specific following syntax:
VARIANCE_REDUCTION
<PARTICLE_TYPE>
WEIGHT_WINDOWS filename
END_VARIANCE_REDUCTION
• <PARTICLE_TYPE> is the particle type related to the weight windows data of the current
VARIANCE_REDUCTION command block and can be either NEUTRON or PHOTON;
• filename is the name of the file containing the weight windows data (with its absolute path) according
to the format detailed in the next section.

## 19.2 WEIGHT WINDOWS FILE SYNTAX

The syntax of the weight windows data file is as follows:

<!-- page 273 -->
WEIGHT_WINDOWS title
FORMAT format_number
GRID energy grid values
MESH or MESH_VARIABLE mesh values ...
... END_MESH or END_MESH_VARIABLE
ADJOINT adjoint flux values ... END_ADJOINT
MODE <ww_mode>
CU_RATIO Cu
CS_RATIO Cs
• title is any chain of characters (a maximum of 256);
• format_number is an integer standing for the format number with the following meaning:
– with format number 1, adjoint flux values are given as such;
– with format number 2, adjoint flux values are given as −ln(φ+), which is consistent with the
way of storing importance values in TRIPOLI-4® and can be retrieved when using the keyword
STORE_IN_FILE with the standard variance reduction technique of the code (see Chapter 17) (e.g.
for an importance map generated by the INIPOND module);
– with format number 3, lower bounds data of weight windows are given, such as provided by version
3.0 of ADVANTG code, with a specific syntax and additional optional keywords detailed in the next
section.
• GRID, MESH or MESH_VARIABLE are required only with format numbers 1 and 2 and the energy grid
values and mesh values follow the same ordering convention as for data dumped when using the keyword
STORE_IN_FILE of Chapter 17;
• For format numbers 1 and 2, adjoint flux values φ+ or −ln(φ+) are given after the keyword ADJOINT,
with the following order of loops (from the most exterior one): the energy group of the grid, then k, then
j, then i (i,j,k being the cell indices);
• MODE is optional and allows the user to choose the event types in trajectories where weight windows
are played during the simulation:
with AFTER_COLLISIONS (which is the default value
for <ww_mode>) weight windows are played before each flight between two collisions; with
BEFORE_AND_AFTER_COLLISIONS they are played before each flight and before each collision; with
AFTER_COLLISIONS_AND_AT_SURFACES they are played before each flight and at each surface crossing
between volumes.
• CU_RATIO is the ratio of upper and lower weight bounds and CS_RATIO is the ratio of survival weights
and lower weight bounds. These ratios are constant for all weight windows and can be chosen as follows:
Cu = 5 and Cs = 3, according to the recommendations in Reference [7].

## 19.3 SPECIFIC SYNTAX WHEN DATA ARE PROVIDED BY ADVANTG CODE

When the format number is 3, then data are directly provided by the output of version 3.0 of ADVANTG code
and the syntax of the weight windows data file is as follows:
WEIGHT_WINDOWS title
FORMAT 3
wwinp_filename
MODE <ww_mode>
#
NOT_FOR_ZERO_VALUES
#
SWITCH_ZERO_TO_MAX_VALUES
CU_RATIO Cu
CS_RATIO Cs
The name of the wwinp file is given just after the format number (3), with its absolute path. The format of the
wwinp file is such as produced by version 3.0 of ADVANTG code.
Cartesian and cylindrical windows are available.
TRIPOLI-4® assumes the following rules if zero values of lower weight bounds are present in the wwinp file:
• In case of a zero lower weight bound for a given cell and a given group, the adjoint flux used by
TRIPOLI-4® in this cell (for the calculation of the biased source and the birth weight of source particles),
is the minimal adjoint flux among the other cells for the same group. Moreover, by default (which is
equivalent to the presence of the optional keyword NOT_FOR_ZERO_VALUES), the weight windows are
then not played in this cell during particle transport simulation (following the same convention as for
MCNP).
• Otherwise, if the optional keyword SWITCH_ZERO_TO_MAX_VALUES is present, the same rule applies for
the source, but weight windows are played in this cell during transport simulation with the maximal
lower weight bound (which is equivalent to the minimal adjoint flux value) for this group.
• The relation between lower weight bounds and adjoint fluxes is used to retrieve importances and to
calculate the biased source of the simulation.

## 19.4 OTHER RELATED SIMULATION OPTIONS

The optional keyword MAX_SPLITTING_PARTICLE_NUMBER can be used in the SIMULATION command block
(see Section 22.2), so as to limit the number of particles possibly split whenever weight windows are played
(the default being 1000).
